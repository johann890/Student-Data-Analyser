Student Data Analyser — how to use it

Start here

This tool answers questions about student enrolment data by letting you build the question out of parts, instead of writing a query in a language. Each part is a node on the canvas. You wire nodes together, and data flows along the wires from left to right.

Every query has the same three-part spine:

  1. A Source — where the rows come from. Every query starts with one.
  2. Processing — any number of nodes that narrow, reorder, summarise or combine those rows. This part can be empty.
  3. An Output — where the answer appears, in the panel on the right.

Nothing is calculated until you press Run Query. Until then the canvas is a description of a question, not an answer to it — so you can build and rearrange freely without waiting for anything.

The quickest possible start: click Source, then Output, drag the Output near the Source until a wire appears, and press Run Query.

The toolbar

Everything you can do to a query lives along the top, grouped by purpose: build it on the left, manage the file in the middle, change your view on the right.

Anatomy of a node

Every node has the same two parts: a coloured shape you drag around, and a settings panel underneath it. The shape says what kind of node it is; the panel says what this particular one does.

Connecting nodes

There are no wires to draw by hand. Drag one node near another and a wire appears between them; drag it away again and the wire goes. Direction is worked out from what the two nodes are, so a Filter dropped beside a Source is always fed by it, never the other way round.

To branch, wire several nodes to the same source: one table can feed any number of downstream nodes. That is how you ask two questions of one population and then bring the answers back together with Compare.

Node reference

The Processing menu groups its eight nodes by what each does to the shape of the table. The colour of a node on the canvas is its group, so you can read an unfamiliar graph at a glance: where it narrows, where it collapses, where branches meet.

Source

Where a query begins. It reads the enrolment rows and hands them on. Every query needs at least one, and a query with none has nothing to compute. Several Sources in one graph is normal — that is how you reach across years.

Filter

Keeps the rows that match a condition and discards the rest. Add more than one condition to narrow further; a row must satisfy all of them. The fields on offer come from whatever is arriving, and the comparison changes to suit the column — a number gets at least and at most, a category gets is and is not.

Reshape rows — violet

Same rows or fewer. The columns are left alone.

Sort
Orders rows by a column, ascending or descending. Add further keys to break ties: the first key decides, the second settles what the first left equal.
Take
Keeps the first N rows and drops the rest. On its own that is arbitrary, so it is nearly always used straight after Sort — together they mean top N.
Unique
Two modes. With no column named it removes duplicate rows, comparing whole rows. Name a column and it returns that column's distinct values instead, one per row — which is how you get a list of the courses or the years present in a table.

Summarise — teal

Rows collapse to a summary, and the columns are rewritten.

Aggregate
Reduces the whole table to a single value: a count, sum, average, minimum or maximum of one column.
Aggregate Columns
One row out, with the chosen calculation applied to every numeric column at once. Use it for a profile of a group rather than a single figure.

Branches — rose

Several tables in, one out. These are the only nodes that take more than one wire.

Combine
Stacks branches on top of each other into one longer table, so the columns have to match. It can merge them, keep only rows present in all of them, or keep only rows missing from the others — which is how you ask who left between two years. Duplicates are kept unless you ask for them to be dropped.
Compare
Puts branches beside each other instead, one column per branch, with a row per measure. Use it to hold two populations up against one another rather than to pool them.

Output

Where an answer appears. Each Output becomes a block in the results panel. A graph may have several, so one run can answer several questions at once. Its setting chooses what to display — the rows themselves, or a figure computed from them.

Reading results

Pressing Run Query fills the panel on the right, one block per Output node, in the order the Outputs were added.

Making the panel wider

The panel starts narrow so that the canvas has room. When a table has more columns than fit, there are two ways to widen it, and the canvas gives up the space rather than being covered.

  • Wide, at the top of the panel, opens it far enough to read a full row at once, and a second press puts it back. W does the same.
  • The edge between the canvas and the panel can be dragged to any width in between. Double-click it to return to the starting width.

Whichever width you settle on is remembered the next time you open the tool. It is a setting of your own, not part of a query — saved .json files carry the graph only, so opening someone else's query leaves your layout alone.

Checking a query rather than trusting it: every node shows its own row count after a run, and hovering a wire shows the table passing along it. Between them you can follow the data step by step and find the point where a result stopped being what you expected.

Saving a query

Save writes the whole graph — every node, its settings and every wire — to a .json file, and asks you to name it first. The .json ending is fixed, so a saved query is always one the tool can open again. Save a second time and it offers the name you used before, so revising a query does not scatter near-identical files.

Load opens one back onto the canvas, replacing whatever is there. Only .json files are accepted.

What a file holds is the question, not the answer. Opening a saved query restores the graph, and pressing Run Query evaluates it against the data as it stands then — so the same query re-run next year gives next year's answer.
